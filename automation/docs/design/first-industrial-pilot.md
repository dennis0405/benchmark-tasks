## 조사에서 확인한 점

서버 메모리·드라이브·PCIe 카드 작업은 실제 정비 근거를 찾기 쉬워도, 이미 제출된 커넥터 장착·체결
능력과 겹칠 수 있다. SKF·ABB 정렬 작업도 원문 근거 외에 기존 측정·조정 태스크와의 비교가 필요하다.
현재 검토하는 단자 추출은 제조사 문서에서 공구·부품 시리즈를 일치시켜야 한다. 같은 설명서의
5556 양측 블레이드 절차와 5378 단일 블레이드·와이어 동반 인출 절차를 섞으면 안 된다.
5378 방식은 별도 형상·로봇 적용 근거가 부족하다. 현재 실행 파일의 선택 ID와 비교 대상 해시를
확인해야 하며, 이전 보고서의 선택 결과를 현재 실행에 그대로 적용하면 안 된다.

## 실행 중 수정한 문제

1. 닫힌 타 팀 테스트 PR의 정보 부족과 현재 accepted/pending 주장 불확실성을 구분했다.
   모든 비교 기록은 남기며 실제 중복과 필수 범위의 정보 부족은 차단한다.
2. 유사 기록부터 비교하고 명확한 중복을 찾으면 즉시 탈락시킨다. 통과에는 전수 비교가 필요하다.
3. PDF 행말 하이픈을 정규화하여 실제 원문의 정상적인 줄바꿈을 허위 인용으로 오판하지 않는다.
4. 팀 인증이 있으면 공식 보드와 GitHub를 함께 수집한다. 보드의 pending 뷰에는 pilot 및 재검토
   기록도 포함되므로 페이지 길이를 pending 요약 숫자와 단순 비교하면 안 된다.
5. 우리 팀 전체 이력은 작성자 추정이 아니라 공식 팀 API로 확보한다. 보드가 숨긴 철회 건
   `TK-ZFPEC9`는 [공식 접수 댓글이 있는 PR #686](https://github.com/robocurve/benchmark-tasks/pull/686)의
   접수 시점 커밋으로 복구하며, 작성자·ID·제목을 재검증한다. 인증·쿠키·비공개 피드백은 worker에 넘기지 않는다.
6. 25건 중 23건만 반환된 응답을 후보의 중복으로 오판하던 문제를 수정했다. 누락 ID만 재요청하고,
   실패는 `CoverageError`로 구분한다. 성공한 개별 비교는 정확히 같은 입력일 때만 재사용한다.

각 중지 때 연구 결과와 실행 기록을 fork에 보존하고 실제 인스턴스 STOPPED를 확인했다.
위 조치가 산업 과제의 신규성·실물 물성·시연 성공을 증명하는 것은 아니다.
